# 단가조정 효율화 서비스 구현 계약 v2.0

2026-11-12 / 공개 개발용 기준. 내부 회의록·개인정보·고객 원문·API 키를 포함하지 않습니다.

## 현재 구현과 목표
현재 저장소는 가상자료·브라우저 저장소 기반 FE 데모입니다. 서버 인증, 실제 기관 연계, 실전자서명, 실제 OCR/LLM 및 송금 구현을 의미하지 않습니다. 기능 연결 MVP는 동일 계약의 구매·공급기업 왕복과 근거 추적을 목표로 합니다.

## 불변 업무 규칙
- FR-01 모든 서버 요청에서 기업 소속·거래 참여·문서 권한 확인. 프런트 역할 전환은 데모뿐입니다.
- FR-06/09 추출 미확정 값은 계산 확정 불가. 숫자는 결정론 계산 엔진이 처리합니다.
- FR-13 원문은 공급기업 비공개. 공유 결과·수신자·목적·기간·버전을 별도 승인합니다.
- FR-14 같은 약정 payload와 버전의 양사 확인만 활성화합니다. 변경 시 낡은 승인 사용 금지.
- FR-15 종료 약정은 active 집계 제외. 갱신 완료는 새 버전·기간·양사 확인 뒤입니다.
- FR-17 정기조정 업무 확인을 합의 산식의 새로운 거절권으로 만들지 않습니다.
- FR-18 계산·PO·청구·지급근거는 별도 상태입니다. 다운로드는 ERP 반영이나 지급이 아닙니다.
- FR-21/22 생성 파일 없이 완료 문구 금지. 제출·접수·인정은 구분합니다.
- AI-01 외부 API는 서버 어댑터에서 승인된 합성자료로만 사용합니다. 자료분류 미상·실제자료·허용목록 밖 endpoint는 전송하지 않습니다. 키를 프런트·git·AI 대화에 넣지 않습니다. 학습 미사용·보관·하위 제공자 정책을 따로 확인하며 문서 작성으로 계정 설정이 변경된 것은 아닙니다.
- AI-02/03 구조화 정답→문서 변형→분리된 평가셋 순서로 데이터 생성합니다. RAG는 가중치 학습이 아닙니다.
- BC-01 테스트넷 명세 지급은 독립 실증이며 실제 자금과 기업 원문을 사용하지 않습니다.

## 동일 거래 인수 시나리오
AL-004 구매 요청 → 공급 S04 보완·원가 산정·공유 승인 → 구매 확인 → 동일 조건 양사 승인 → 활성 → 정기 계산 → PO·청구·지급근거 각각 확인 → 권한 있는 증빙 출력. 갱신과 이견은 별도 버전으로 보존합니다.

## 인터페이스
계약·문서·추출·원가검토·공유·약정·승인·계산·대조·패키지 API를 분리합니다. 금액은 Decimal 문자열, 시각은 UTC 저장/KST 표시, 상태변경은 expected_version 및 Idempotency-Key를 사용합니다. 401/403/409/422 오류는 다음 행동을 포함해 표시합니다.

## 합성자료와 평가
필수 후보: 계약/PO, BOM·소요량, 국내 기구매 세금계산서+거래명세서, 기존 약정·확인서, Invoice·지급근거. 신규 구매는 견적서 2개 이상, 수입은 신고필증·부대비용 등 사례별로 다릅니다. 모든 문서가 모든 거래의 필수는 아닙니다. 세금·단위·기간·배부 기준을 문서 간 대조합니다. 100독립사례 제안(개발60/검증20/동결20), 회사·템플릿·거래 그룹 단위 분리. 핵심수치95% 목표, 계산100%, 무근거 확정0·타사 접근0을 인수 목표로 합니다.

## AI 작업 인수인계
요구사항 ID / 허용파일 / 입력·출력 / 상태·권한 / 예외 / 테스트 / 미구현 / 커밋을 기록합니다. 팀 AGENTS.md를 먼저 읽습니다. 패키지·빌드 설정은 임의 변경하지 않습니다. 반영 방식은 저장소 협업 규칙과 인증된 작업자 계정을 따릅니다. 기업 원문·비밀키·비공개 회의록은 AI 도구 문맥이나 공개 저장소에 올리지 않습니다.
